# Executable protocol amendment: v2

Current implementation: see the [frw-v3 amendment](PROTOCOL_V3.md) for LR/head selection and the five adopted measurement improvements. The v2 notes below are preserved as design history.

This amendment accompanies the original DOCX documents, which are left intact. It records changes made before any study data were generated by this redesign. The model identities are fixed exactly as requested. Existing v1 results must remain in a separate directory.

## Fixed scientific design

Four base checkpoints: meta-llama/Llama-3.2-1B; Qwen/Qwen2.5-1.5B; ibm-granite/granite-3.3-2b-base; Qwen/Qwen2.5-3B. Exact model/tokenizer commit hashes and the GLUE dataset commit are in `rank_suite/config.py`. Loading uses safetensors and disables remote model code. Architecture dimensions are checked against the registry.

The main design is 4 models × (5 LoRA ranks + 1 non-embedding full-FT baseline) × 5 seeds = **120 sequential runs**. Rank is 4/8/16/32/64, seeds are 42/123/456/789/1024, alpha=2r, q/v targets in all layers. One adapter/weight set persists over RTE → MNLI → SST-2. One seeded linear last-nonpadding-token head per task is used; only the current head trains. Previous heads are frozen, and every earlier task is evaluated using its own head.

Training uses 2,490 examples per task, drawn once with data seed 42; RTE uses its entire 2,490-example training split. Every main run uses three epochs/task, effective batch 16, the nominal per-track model LR from the literature review, 3% warmup rounded up to an optimizer step, cosine decay, betas 0.9/0.999, optimizer epsilon 1e-8, weight decay 0, gradient clipping 1.0 and dropout 0. Optimizer states and schedule restart at each task. There are 156 updates/epoch, 468/task and 1,404/sequence. A final partial batch of ten examples is retained and normalized by its actual example count.

Across-seed SD and paired uncertainty intervals measure initialization/shuffle variation on these fixed examples; they do not estimate uncertainty over new task orders or unseen populations. The stored `forgetting_magnitude` field is signed −BWT and can be negative when earlier-task accuracy improves; it is not an absolute value. Analysis recomputes metrics from the raw accuracy matrix.

Official validation sets are evaluated in full after each boundary: RTE=277, MNLI matched=9,815, SST-2=872. No early stopping or best-epoch selection is performed. Evaluation predictions and labels are saved so accuracy and uncertainty can be independently checked. All task diagonals and the entire accuracy matrix are retained.

## Deliberate amendments

| Item | v2 decision | Reason |
|---|---|---|
| Default ranks | Entire five-rank grid | A default rank-16 run does not answer the rank question. |
| Parameter precision | Trainable weights and heads fp32; frozen LoRA backbone bf16 except fp32 normalization layers in both tracks; bf16 autocast matmuls | Preserve small optimizer updates and consistent normalization policy. No model-weight quantization. |
| Optimizer | **LoRA:** standard AdamW, fp32 moments. **Full FT:** AdamW8bit, block-wise matrix moments, min_8bit_size=0, percentile clipping=100, non-paged; fp32-state overrides for heads and 1-D normalization/bias tensors | Primary rank comparisons have uniformly fp32 optimizer states. Full-FT memory is reduced without an outcome-dependent precision switch. Its different moment precision is a declared limitation of the cross-track comparison. |
| Alternative optimizer | `--optimizer adamw` applies to the entire experiment | Optional fp32-state robustness cohort, requiring more VRAM. Never mix its results with the default cohort. |
| Micro-batch | Default 4 × accumulation 4, same across tracks/ranks | Conservative memory baseline. Set 8×2 or 16×1 once, before starting a new experiment, if its pilot fits. No silent OOM fallback. |
| Eval batch | Default 32 | Less peak memory. It remains fixed within an experiment; full validation is preserved. |
| Autocast weight cache | Disabled | Avoid keeping an extra bf16 copy of all fp32 trainable weights alive during the forward context. |
| Pair encoding | Explicit “Premise:” and newline “Hypothesis:” fields with longest-first truncation | Decoder base tokenizers may concatenate text pairs without a separator. Markers keep the two fields distinguishable. SST-2 uses “Text:”. |
| Padding | Right dynamic padding to a multiple of 8, max length 256 | Tensor-core-friendly batch shapes; correct last-nonpadding-token pooling. |
| Spectral stage | Export exact parameters at all boundaries; analyze later on CPU | No CPU decomposition while a rented GPU waits. Full-FT projection snapshots retain fp32 precision. |
| Intruder definition | Top 10 tuned left vectors vs **all** pretrained left vectors, absolute cosine, eps=0.6/0.7/0.8/0.9 | Correct the old top-ten-reference implementation. |
| LR sanity | Fifteen unique single-task runs on an 80/20 stratified training holdout | Correct arithmetic and keep official validation separate from sensitivity decisions. No automatic LR fallback. |
| Window baseline | The declared nominal full-FT LR, all five seeds | Never choose a baseline by looking for the highest reported accuracy. |
| Window completeness | All five ranks, exact five prescribed seeds and five-seed baseline required per model/LR | Partial experiments cannot silently produce confident recommendations. |
| Uncertainty | Sample SD (ddof=1), paired seed differences with exploratory t intervals | Same variance convention in figures and tables; no single-seed conclusions. |

Both tracks use the same AdamW betas, epsilon, decay and clipping, but their moment precision and nominal LR differ. The baseline compares these declared training policies; it does not isolate adaptation method independently of optimizer precision. A separate `--optimizer adamw` cohort tests that limitation when memory/budget permit.

## Modes and reuse

`main` runs the selected part of the main grid. `pilot` runs r=16 and full FT at seed 42 with full data/epochs/evaluation: these are ordinary main results and are reused by later main execution. `smoke` trains 64 examples/task for one epoch and evaluates at most 32 examples/task, under `<output>/smoke/`. Its purpose is software validation. `sanity` trains RTE on 1,992 examples and evaluates the 498-example training holdout under `<output>/sanity/`; the LR pairs follow methodology §11. Neither diagnostic mode contributes main results.

An unstable run stops the batch by default. Grad-norm spikes are recorded relative to the preceding 50-step median after ten history steps; nonfinite loss, logits or gradients fail the run. Flags remain visible, and failed/incomplete runs do not enter aggregates. `--keep-going` is an explicit diagnostic override. There is no automatic deletion of difficult seeds, rank-specific LR tuning, reduced final evaluation, or shortened main training.

## Spectral numerical policy

The pretrained reference is a full fp32 CPU SVD, cached without reducing vector precision. Tuned top vectors default to a deterministic dense float64 Gram eigendecomposition selecting the leading eigenvectors, then fp32 cosine evaluation. This computes the same left singular directions while avoiding unused right vectors; [SciPy documents the subset eigensolver](https://docs.scipy.org/doc/scipy-1.15.3/reference/generated/scipy.linalg.eigh.html). `intruders --solver svd` performs direct fp32 SVD as a cross-check. Similarities within 1e-4 of a threshold trigger a direct-SVD recheck and are flagged. Closely spaced singular values can still make individual vectors sensitive; examine flagged matrices and threshold sensitivity.

Analysis resumes after each matrix. Base snapshots and boundary snapshots have SHA-256 checksums. Derived caches are separated by base-content hash, analysis version, solver and boundary checksum. Full-FT counts can be nonzero. Decompositions cover all q/v matrices at every boundary, including full FT; no selective-layer or seed shortcut is used. The full main design has 21,600 tuned decompositions plus 240 pretrained reference decompositions, so CPU analysis is substantial work rather than “trivial.”

## Reproducibility and interruption policy

An output directory contains immutable protocol and software records, per-model GPU-type records, and an append-only directory of invocation manifests with the exact installed package freeze. Source hashes, revisions, optimizer, batch partition, precision and deterministic policy are checked. Changing these requires a new output directory. Grid subsets, seed blocks, price estimates and shard selection can be extended without changing the scientific controls.

Run IDs hash the actual LR and training identity, rather than rounding the LR into a filename. Completed runs are skipped before model/data loading. Task-boundary recovery saves the adapter or full current state, all heads, RNG state, matrix and logs; fresh per-task optimizer states make this sufficient for restarting the next task. An interrupted task itself restarts. Atomic file replacement and Linux kernel locks prevent incomplete completion markers and duplicate workers. A finished run removes only its temporary resume checkpoint; boundary artifacts remain.

One process uses one GPU. Shards keep each model/seed's ranks and baseline together. Per-model hardware locks prevent running its ranks or baseline on different GPU types in one experiment. Different models can use different GPU types, but those differences must be reported and weaken cross-model interpretation. Bitwise equivalence across GPUs/drivers is not promised. `--deterministic` enables strict deterministic algorithms; otherwise seeds and numerical policies are still recorded.
